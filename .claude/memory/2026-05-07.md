## 設計判断

### (a) compile-time path 検証を `CompileError` 化(後方非互換、Option A 選択)

### (b) `is_relative_to` 防御を 3 surface で対称化

- `validate_plan._resolve_package_root:129-138` には既に存在
- `check.py:200-206` / `pre_commit.py:221-227` には**同じ性質のチェックが無い** → 内部非対称 = code review red flag

- `tree_root` も resolve した上で `path.is_relative_to(resolved_tree_root)` を判定(既存 validate_plan のパターンを踏襲)

### (c) coverage `fail_under=70` の根拠

- 現状実測 **branch coverage 72.81%**(line のみだと ~75%)
- `fail_under=70` で **~3pp margin**(初期コミットで「~5pp」 と書いていたが、branch coverage 計測後に再測 → コメント訂正コミット `1ed9f03` 別途 push)
- 哲学: **threshold は現状 - α** で gate が fail しない位置に置き、上向き調整は手動。下方変動に強く反応する設定

### (d) `pip-audit --strict .`(プロジェクトパス指定)で env-level CVE 汚染を遮断
