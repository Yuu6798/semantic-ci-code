- catalog builder は `authoring/catalog.py` に置いた。
- registry 値は catalog 内で hard-code せず、 runtime registry を再 import して mirror する。
- 参照元は `compiler/path_schema.py`、 `compiler/type_schema.py`、

  `framework/constraint_types.py` / `compiler/operator_schema.py`。
- JSON envelope は `schema_version="catalog-1"` / `subcommand="target-catalog"`。

## メモ

- CSCI-44 は「AI が target.yaml を正しく書くための authoring meta surface」であり、
  verdict には参加しない。
- catalog は advisor surface だが、 runtime registry を読むため implementation と強く同期している。
- そのため INV-2 surface isolation と INV-5 implementation parity を同時に守る必要があった。
- `target-catalog` は target.yaml を必要としない。
- `target-catalog` は git / extractor / network を必要としない。
- `target-catalog` は LLM を呼ばない。
- `target-catalog` の value は registry mirror であり、 authoring UX の説明文を勝手に盛らない。
- JSON は external tools 向け、 human は人間 authoring 向け。
- Brief 8 完走により、 target.yaml authoring path は docs / doctor / init recipe / catalog の 4 面が揃った。
- ここから先の SSP は別軸。semantic-ci の core authoring loop は一段落。
