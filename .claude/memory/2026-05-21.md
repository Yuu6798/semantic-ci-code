## 設計判断

### Brand / framing

- **「Semantic CI Ecosystem」 ではなく「UGH ecosystem」 が正しい
  brand**。 UGH (Unconscious Gravity Hypothesis) が理論基盤、 UGHer /
  UGH ecosystem が ecosystem 名、 「semantic CI」 / 「semantic audit」
  は ecosystem 内の design pattern 名。 user 冒頭の「セマンティック CI
  エコシステム」 呼称も pattern 軸からの呼称であって product brand では
  ない、 を web fetch 後の発見として user と合意。
- **4 active domain + 1 archived init + theory foundation** の構成:
  - Text — `ugh-audit-core` (最 mature、 HA48/HA63 validated)
  - Code — `semantic-ci-code` (最 disciplined、 ABCD-A/B 完走、 0 tag)
  - Music — `ugh-prompt-engine` (PoC、 2 tag、 217 commits)
  - Image+Video — `svp-video-pipeline` (experimental、 paid run、
    Claude planner + deterministic audit hybrid)
  - Archived init — `ugh3-metrics-lib` (UGH 理論初期 code 化試行、
    現在 touch されていない)
  - Theory — UGH note.com 記事 (現時点 公開戦略凍結、 umbrella で
    explicit citation しない)

### Strata (2 軸architectural separation)

- **Audit layer (全 domain で必ず deterministic)** ← § 23.1 input
  neutrality の ecosystem scope 表現
- **Generation layer (domain で異なる)**:
  - Text / Code / Music = generation せず audit のみ
  - Image+Video = Claude planner + image/video backend で生成、
    audit 部分は deterministic
- これが「semantic-ci-code の scope guard 半年厳守」 の真の payoff
  だった、 と本 session で言語化された。 scope guard は「LLM を core
  に入れない」 為の規律ではなく、 **LLM 生成を別 strata に押し出して
  deterministic auditor identity を保つ** ための ecosystem 規律の
  code domain 実装。
