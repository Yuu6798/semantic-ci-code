## 設計判断

- **ordinal を v1 identity に今入れる (G-1 repair)**: PR #124 初版は SAST
  identity から `ordinal` を脱落させ、同位置重複 finding が canonical_id 衝突 →
  SensorState uniqueness validator で reject される穴があった。後 (G-2) で ordinal
  を足すと identity shape 変化 → 全 canonical_id 変化 → v1→v2 強制 bump という
  高コスト migration を招くため、v1 のうちに ordinal slot を確定。
- **SAST identity を SSP v0.1 5 要素 fingerprint に整合 → 8 要素**:
  planning 当初案 (`fqn` / `normalized_text_hash` / 7 要素) ではなく、impl が
  選んだ `(v1, sast, sensor_id, rule_id, module_path, qualified_name,
  normalized_text, str(ordinal))` を canonical 形に採用。移植元 SSP の
  fingerprint 構成と一致させることで G-2 翻訳が同じ識別軸を使える。
- **Suppression を G-3 に defer / SensorState を観測状態に純化**: PR #124 初版は
  Suppression を SensorState に埋め込んでいた (観測 vs 宣言ポリシーの混同)。
  planning §1.1 の概念分離に従い SensorState は findings + provenance のみに純化、
  Suppression は target.yaml security namespace の一部として G-3 (CSCI-47) に移送。
- **G-2 = 薄い翻訳層 (SSP adapter 再利用)**: full port (~600 行重複) ではなく、
  SSP の `from_json` を呼んで SensorOutput を得て型変換のみ。planning §4 の段階
  移行 (full 吸収は G-4) と整合。`sensor/adapters/` は ssp を import 可だが
  `sensor/models.py`+`delta.py` は ssp-free 維持を isolation test で構造保証。
- **SCA dedup の非対称性 (G-2 review)**: SAST は `assign_sast_ordinals` が
  dedup+採番で衝突回避するが、SCA は素通しで重複 advisory → canonical_id 衝突 →
  crash。SSP `_dedup_fingerprinted` を鏡像して SCA 側も canonical_id dedup
  (keep-first) が必要。
