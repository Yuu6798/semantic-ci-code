## 設計判断

- **G-4 を 4a / 4b に分割**: G-4a で「sensor ingest + 集約 verdict + exit code」
  という最小の縦動線を先に通し、G-4b で「per-sensor 詳細 + SARIF」を additive に
  積む 2 スライス構成。G-4a 時点では `--format sarif/gh-actions` を明示 reject し、
  G-4b で sarif を解禁・gh-actions のみ defer。verdict / exit semantics を G-4a で
  凍結し、G-4b は純粋な出力 enrichment に限定 → review の attention budget を分離。
- **CSCI-48b brief の grounding-first 起草**: brief を書く前に `evaluate_security`
  の内部 (per-sensor loop が detail を捨てて集約 status のみ返す) / SecurityFinding
  の field / SARIF result mapping を逐語 read。これにより brief に 2 つの「予定された
  破壊」を事前 encode できた: ① `evaluate_security` を `evaluate_security_detail`
  への薄い wrapper に再実装 (既存契約維持) / ② G-4a の `security == {verdict,
  as_of}` exact-match assertion を subset assert に緩和 (これを書かないと CI 赤)。
- **設計確定を AskUserQuestion で 2 軸 pin**: 粒度 (完全詳細 vs 集約のみ) と SARIF
  配置 (同一 run マージ vs 別 run / 非対応) を選択肢化。user は「完全詳細 + 同一 run
  マージ + severity→level (critical/high=error, medium=warning, low/info=note)」を
  選択。実装はこの 3 点をそのまま AC 化。

## 設計判断 (D1〜D9、doc に encode 済)

- **D1 中心命題「LLM は scout であって judge ではない」**: on-demand / optional /
  非常駐。LLM 出力は Advisor surface に流れ verdict を直接 seat しない。合否を出すのは
  決定論的宣言制約 (target.yaml)。これが scope guard「not an LLM-as-judge service」
  との衝突を解消する核。
- **D2/D3 決定論保全**: LLM は core の外、frozen SensorState を ingest (Phase G
  再利用)。§23.1 / Sensor Provenance Invariant は「記録された出力から再現」なので
  weaken しない。ただし LLM は「入力固定でも揺れる」新 wrinkle を持つ → D4 で吸収。
- **D4 one-run + 決定論的 re-projection**: 2 回独立 scan の差分は unsound (recall
  ノイズが added/removed を汚染)。candidate に 1 回 scan → 各 anchor を baseline へ
  決定論的に再投影。
- **D5 LLM-general Adapter Protocol**: Codex Security = first concrete。クロスモデル
  集約は「自動」ではなく明示ステップ (pre-SensorState dedup or ensemble identity)。
- **D6 anchor projection (暫定)**: Phase G canonical_id 空間へ射影。具体レシピは
  実装時較正 = 暫定固定 (user 判断: 実務上の設計判断なので暫定にして実装時組み替え)。
- **D7 誤検知 > 見逃し**: 高 recall / 細粒度 anchor / 決定論判定不能なら added に倒す
  (炙り出せれば検証できるが見つからなければ検証すらできない)。
- **D8 昇格は authoring freeze のみ・沈黙 = 容認**: 自動昇格なし。target.yaml に
  起こした時点 (human/AI 問わず) で制約化。無宣言 = 作者の容認 (§23.3「intent
  validator/interpreter ではない」。vacuous PASS と別物)。scout の役割は「沈黙を
  無知から承知へ変える」。
- **D9 informed-consent を provenance 記録・waiver = advisory mute**: verdict 非参照。
