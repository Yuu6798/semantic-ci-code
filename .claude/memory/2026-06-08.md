## 設計判断

1. **「release vs no release」→「stability promise vs no promise」に軸をずらした。**
   SemVer/PEP440 は 0.x を「いつでも壊れてよい」と定義するので、安定保証ゼロの
   まま tag を刻むことは可能。ただし本人判断で **tag は切らない**(0.0.x も見送り)。
   credibility の本体は「experimental ラベル」でなく **falsifiable な v0.1.0
   exit criteria** の側にある、と整理。
2. **ROADMAP exit criteria を反証可能形に**: schema_version が連続 3 brief 不変 +
   exit-code policy 不変 + D1〜D7 全解決/waive。N=3 は「早切り回避=凍結ゲートは
   保守側」の根拠付き。配布(PyPI/Action/semver1.0)は post-Phase-X に deferred と
   明記し STATUS と整合。
3. **doc bloat 回避**: credibility 素材は README/ROADMAP/CONTRIBUTING/examples の
   reader-facing 最上層に置き、canonical doc へは link DOWN only(deep doc を
   増やさない)。
4. **G-5 = auth-guard 抽出 (Category B)**。grounding で Category A
   (deny imports/effects) は既に recipe 実装済みと判明 → 冗長な
   `templates/security/` static dir は作らず、本当に新規価値のある Category B を
   G-5 に。planning の `auth_guards_delta` を **汎用 config-free `decorators_delta`
   + recipe の allowlist** で realize(delta 層を domain 非依存に保ち §23.1 維持、
   「not an intent interpreter」を侵さない)。path_schema / evaluator は
   schema 反射で**変更不要**。
5. **G-6 を G-5 に畳んだ**。planning §G-6 (CSCI-50) = auth guard と
   llm_sensor §H-1 (CSCI-50) が番号衝突 → G-6 枠を廃し CSCI-50 は Phase H に一本化。
