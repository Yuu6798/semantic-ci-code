## 設計判断

- **D6 = tracker candidate path (a)**: ADVISORY-D6 検出器 + guide Hazard 4。
  path (b) (extractor が nested entry を emit する spec 変更) は
  schema-impacting のため不採用のまま長期 option として tracker に残置。
- **D6/D7 とも D4 の diff-aware 契約を鏡像**: detector は純粋関数、
  diff 由来 context (`NestedDefGrowth` / `VisibleDefGrowth`) は CLI 層
  (`_resolve_diff_context`) が計算。rev 未指定 + git 不在は silent skip。
- **可視 def カウントは extractor 本体に委譲**: `count_visible_defs` は
  `extract_python_complexity` の emission 数をそのまま使い、parity drift を
  構造的に排除 (D7)。nested カウントは独立 AST walk (D6)。
- **D7 の発火条件は「+net を reject する lock」**: net 増加 +N を先に計算し、
  evaluator の tolerance semantics (`le: observed <= expected + tol`、equals
  は tolerance 非適用) を逐語 mirror して「観測される +N が violate するか」
  で判定。固定 +1 判定や per-file 正判定は Codex review で 2 段階に
  反証された (下記)。
- **advisory envelope を advisory-2 に bump**: compatibility policy は使用中
  enum への値追加に bump を要求。D6 (PR #152) の in-place 追加も未リリース
  main 上だったため本 bump に畳んだ。
- **ugh-prompt-engine 移植は「形式適応」**: wrap-up skill / discipline テスト
  を同 repo の慣例 (英語 STATUS 見出し / `_index.md` 箇条書き / pytest-cov
  非依存) に合わせて移植。documented gate command の `--no-cov` が
