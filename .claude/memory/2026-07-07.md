## 設計判断

- **ルールの置き場所を 2 層に分割**: 常時ロードが必要な操作ルール本体は
  `CLAUDE.md ## Workflow` の Model split 節 (300 行 cap 内に収めるため
  Tier D 重複文削除 + Tech Stack 散文化で行数捻出)、根拠・委譲対象表・
  運用詳細は `docs/model_delegation_policy.md` (ACTIVE) に外部化。repo
  自身の「CLAUDE.md は lean、詳細は docs/」規律に従った。
- **ルールの核心は「コール数 × 戻り値の重さ」の AND**: 実測でトークン
  主燃焼源は修正作業ではなく GitHub ツール戻り値ペイロード (スレッド
  全文再取得・返信の echo)。よって 1 コールでも重い操作 (スレッド取得・
  返信投稿) はコール数によらず常時委譲。
- **拡張調査は本ルートの初適用**: 調査 (capability inventory + design-doc
  seam) を Sonnet 2 並列に委譲、Fable は distilled summary から S1〜S8
  findings を判定し Wave 1〜3 / CSCI-56〜61 に構造化。見送り (S3/S4/S5)
  も declared asymmetry として明示 pin。
- **Wave 3 の gate は X-2 本実験** (pilot は配管確認のみで evidence を
  生まない) — Codex 指摘で pilot-gate の内部矛盾を訂正。
