## 設計判断

### D2-1(in-process CLI invocation)

- **数値ゲートを brief AC に明示**(`pytest -q --no-cov` を `<30s` で gate): 主目的が
  時間短縮なので numerical evidence を要求。 PR body に before/after を必ず記載させた
- **subprocess を残すべきテストの基準を 2 軸で固定**: (a) PYTHONHASHSEED は in-process
  では効かない / (b) console script entrypoint validation 必須 → これら以外は in-process
  化。 sitecustomize cache-hit sentinels は D2-1 では subprocess 残置、 D2-2 で
  in-process monkeypatch に置換
- **`run_semantic_ci = run_semantic_ci_inproc` の alias 1 行で call site 一括書換を
  回避**: 既存の test 200+ 件を機械的に変更しない。 subprocess が必要なテストだけ
  `run_semantic_ci_subprocess` への明示呼び出しに切替
- **`@pytest.mark.slow` + `addopts = "-m 'not slow'"` で wallclock 比較 test を default
  除外**: `test_smoke_is_faster_than_full` 単体で 9.5s、 default 実行から外して
  通常 iterate に乗せない

### D2-2(git fixture reuse + selective migration)

- **fixture reuse + migration を 1 PR で同梱、 split しない**: 同じ `tests/cli/`
  ファイルを触るので split すると conflict / 二度手間。 LoC 想定 ~250 で 1〜1.5 day
  brief サイズに収まる
- **safety テスト全保持** を AC に明記: brief constraint「safety テスト退化禁止」 を
  `worktree cleanup / shallow clone / dirty / git-not-found / staged-index /
  determinism subprocess / cache-hit sentinels / no-fetch / invalid-baseline-ref` の
  9 項目にリスト化、 Codex の判断 grey area を消した
- **<150s 未達リスクを brief 起草時に明示**: Linux 観測のみで設計、 Windows per-call
  cost は推定値。 「<150s 必達 / <90s stretch」 という 2 段ゲートで risks セクションに
  原因分析を要求 → PR body に「real git/worktree/staged-index coverage が頭打ち、
  D2-3 (xdist) 推奨」 と記録され、 D2-3 判定根拠が確定
- **`shutil.copytree` を Windows 優先**(brief 提案は POSIX 同様 git clone を最初に
  試す形だった)→ Codex 実測判断「Windows では tiny repo だと git clone の方が遅い」
  に基づく工程内最適化、 妥当

### ResultStatus 概念モデル更新(`docs/brief_resultstatus_planning.md` 起草)

- **A 不採用 / C+B 仮固定**: A (enum 拡張) は status enum を「判定状態」 と「失敗
  原因」 が混ざる形にする(`status` の意味侵食)。 B (`unknown_cause` sibling field) +
  C (authoring を compile-time に押し戻し) のハイブリッド。 命名は `failure_mode`
  より `unknown_cause` で **狭く**(VIOLATED / SKIPPED に creep しない名前)
- **D2: authoring-cause は `unknown_policy` を尊重しない**(強制 fail): 壊れた spec を
  `unknown_policy: warn / ignore` で握り潰せると gate の意味が消える。 `unknown_policy`
  は本来 extractor failure 用(`design.md §5.4`)
- **D3: `risk_summary` を `would_violate` と `authoring_errors` に分離**: AI generator に
  「実装を直せ」 と「仕様を直せ」 を混同させない。 validate-plan envelope を v1 → v2 bump
- **D4: verdict / compile envelope は据え置き**(nested optional diagnostic field 追加は
  bump 不要 という例外規定を `docs/json_schema.md` に明記する方針、 D1-4 同梱)
- **5 brief 分割**: D1-1 (planning、 本セッション完成) / D1-2 (`E_OPERATOR_TARGET_MISMATCH`
  → compile) / D1-3 (`E_TYPE_MISMATCH` shallow → compile) / D1-4 (`unknown_cause`
  field 追加) / D3 (validate-plan v2)
- **Brief D1-1 deliverable に静的型カテゴリ + operator 行列を含める**: target path 静的
  型 (state 13 / delta 32 path) と operator 20 個 × required category の行列、
  compile-catch coverage 推定(`E_OPERATOR_TARGET_MISMATCH` 100% / `E_TYPE_MISMATCH`
  observed-side ~95% + expected-side 100%)を planning doc §4 に表化
