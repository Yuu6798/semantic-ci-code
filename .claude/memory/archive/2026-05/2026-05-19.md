## メモ

1. **canonical module の docstring を producer reference 集約 site にした
   選択** は今後 Brief 8b (LLM 経路) でも同 pattern が再利用可能。 LLM
   生成の値が canonical 違反なら authoring layer で reject する gate を
   `is_canonical_*` で表現できる。
2. **architecture test の prefix match (`module.startswith(banned + ".")`)
   は新 module 追加時に自動で cover してくれる**設計が、 本 refactor で
   実証。 CSCI-44 で新規 catalog module を追加した場合も `AUTHORING_
   FORBIDDEN_FOR_VERDICT_PATH` の現状 enumeration で自動 cover される
   想定 (`semantic_ci_code.authoring` prefix 配下にあれば追加 enumeration
   不要)。
3. **dogfood で「allowlist 無し fail + allowlist 有り pass」 を **両方**
   見せる pattern** は CI integrity test の最小単位として強い。 single
   case dogfood は no-op gate (D5 FINDING-1 と同じ trap) を検出できない。
4. **Codex 不在の **連続** 2 session の規律負債** は本 session までは
   抑えられたが、 もう 1 session 続くと CSCI-44 を Claude 単独で押し込む
   選択肢が現実的に上がってくる。 その判断点で再度 trade-off 軸 (規律負債
   × 速度 × CSCI-44 規模) を user 判断にかける必要あり。
